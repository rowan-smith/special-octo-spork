# Compatibility audit: 0.1.2

The [COMPAT-GATE-0.1.2](https://github.com/rowan-smith/Vyrtel/issues/229) audit: every
backward-compatibility path found before 0.1.2, what happened to it, the format-version reset,
the supported contract and the verification. It follows the
[pre-1.0 compatibility policy](../../CONTRIBUTING.md#compatibility-policy-before-10) and is the
worked example for later releases' gates
([releasing](../releasing.md#pre-tag-compatibility-sign-off)).

The reviewer's PASS for the final candidate (its SHA, artifact hashes and links to this page) is
recorded on the `release-evidence` branch at `compat/0.1.2/COMPAT-GATE-0.1.2.json`, not here: a
record in the candidate would change the commit it approves.

## Summary

* Every persisted format is at **version 1 of layout `0.1.2`**, and every file carries that
  **layout identity**. All readers, writers, version dispatch and migration code for the
  earlier layouts are deleted.
* 0.1.2 starts **no data directory an earlier release wrote** (0.1.1, Observer 0.1.0, or a 0.1.2
  build before the reset). It refuses them before anything changes, with what to do; the way
  forward is a new data directory
  ([configuration](../configuration.md#upgrading-between-pre-10-releases)).
* Two undocumented API aliases are removed, and unknown setting-like environment variables now
  stop startup instead of being ignored.
* **No exceptions** were requested or approved. No dependency was compatibility-only.

## Inventory

Each path: where it was, the contract it kept, its callers, what replaced it and the data or
security impact. *Removed* paths are gone from source, tests and docs; *retained* paths are
current interoperability or safety, with the evidence.

### Storage: WAL, segments, event codec

| Path / symbol | Old contract | Callers | Outcome | Impact |
|---|---|---|---|---|
| `storage::codec::decode_batch`, the codec-1 branch (resources inline) | 0.1.1's WAL batches replayed by later builds | recovery replay, `check_record_formats` | **Removed.** One batch layout (resource table), codec version reset 2 → 1 | 0.1.1 WALs are refused by their header identity before any record is decoded |
| `codec::encode_batch_v1`, `encode_event`, `decode_event` | write/read the codec-1 layout (tests of 0.1.1 data) | `crates/storage/tests/recovery.rs`, codec tests | **Removed**; the head/body round trip is tested directly | none |
| `wal::header_version`, 24-byte WAL header with no identity | WAL file format 1 as 0.1.1 wrote it | replay, `check_wal_format`, `check_record_formats` | **Replaced** by a 32-byte header with the layout identity after the magic; `wal::identify_header` checks magic → identity → version | a header without this identity, or cut inside it, is refused, never replayed or quarantined |
| `wal::OBSERVER_WAL_MAGIC`, `ReplayError::Observer`, `segment::OBSERVER_SEGMENT_MAGIC`, `StorageError::ObserverFormat` | recognise Observer 0.1.0's magic bytes and refuse them by name | recovery, `check_formats`, datadir | **Removed.** Generic identity refusal (`StorageError::ForeignLayout`); Observer directories are refused as a whole (no identity in manifest or metadata) | an Observer file copied into a 0.1.2 directory is quarantined as damage (moved, never deleted); documented |
| Segment header 32 bytes / footer 56 bytes, no identity | segment format 1 as 0.1.1 wrote it | `Segment::open`, `check_segment_format` | **Replaced** by a 40-byte header and 64-byte footer, both with the identity (the footer's under its CRC) | another or missing identity refused; a header identity the checksummed footer contradicts is damage |
| Version-dispatch rule "keep the decoder for every older version" (`docs/storage-format.md`) | open-ended reading of older formats | format changes | **Replaced** by [Layout changes](../storage-format.md#layout-changes): new identity, versions reset to 1, no old readers | — |

### Data directory, manifest and metadata

| Path / symbol | Old contract | Callers | Outcome | Impact |
|---|---|---|---|---|
| `datadir::Layout::Unversioned` | a directory without `vyrtel.json` (0.1.1 and earlier) is started and gets one | `check`, `App::build` | **Removed.** Without a manifest only an interrupted first start of this build is accepted (`Layout::Unrecorded`: no telemetry, metadata absent/empty/this layout) | 0.1.1 directories are refused unchanged |
| `datadir::Step::{RecordFormat, UpgradeFormat, MigrateSchema}`, `datadir::plan` | the upgrade plan `check-data-dir` printed and a start ran | `report`, `App::build` | **Removed**; `report` says what a start changes (create, finish a first start, nothing) | `check-data-dir` output changed |
| `datadir::RELEASES`, `readable_since`, the release-row step in `docs/releasing.md` | which releases read a directory after an upgrade (downgrade guidance) | `report`, unit test | **Removed**; the release table is in [configuration](../configuration.md#upgrading-between-pre-10-releases) | — |
| `datadir::FORMAT = 2` and format-1 acceptance | 0.1.2 builds before the reset read format 1 and 2 | `read_manifest` | **Reset** to 1; a manifest is read only with `"layout": "0.1.2"` | earlier 0.1.2 builds' directories are refused |
| `Manifest` ignoring unknown keys | forward tolerance for added keys | `read_manifest` | **Removed**: `deny_unknown_fields` | an unknown key is `BadManifest`, not silently ignored |
| `DataDirError::{NewerFormat, Observer, NewerMetadata}` | version-ordered refusals | `check` | **Replaced** by `ForeignLayout` (one message: what has which identity, what to do) and `UnsupportedFile` (same layout, other version) | actionable message, exit status 1, nothing changed |

| Migration hint in `App::build`, `upgrading the data directory` / `data directory upgraded` logs | operator guidance for resumable migrations | startup | **Removed** | — |
| `tests/integration/upgrade.rs` | 0.1.1's fixture is upgraded and reads like its release | CI | **Replaced** by `tests/integration/layouts.rs`: the 0.1.0 and 0.1.1 fixtures are refused with every file hash unchanged; this layout restarts and restores | — |
| `tests/fixtures/datadir/v0.1.0`, `v0.1.1` | upgrade sources | layout tests | **Retained** as refusal fixtures (real files that say version 1 but have another layout) | — |
| Backups (`scripts/backup/restore-drill.sh`) | a backup is a copy of the stopped data directory; no separate container format | CI restore drill | **N/A**: no format of its own; a restored copy passes the same identity check | — |

### Authentication and sessions

API keys are `vyr_` only (`auth::new_api_key`), sessions and users live in the metadata schema
with no migration or key-format fallback.

| Path / symbol | Old contract | Callers | Outcome | Impact |
|---|---|---|---|---|
| `auth.enabled` / `VYRTEL_AUTH_ENABLED`, `Principal::Open` | `false` (the default) opened the UI, API and ingestion | operators, test harnesses | **Removed.** The UI and API always need a login or an admin key; the setting is refused at startup with the replacement (`config::REMOVED_SETTINGS`) | a 0.1.1 install without authentication must sign in with the admin password printed on first start (or `auth.admin_password`) |
| ingestion authentication | tied to `auth.enabled` | producers | **Changed**: required while an ingest-scoped API key exists, open while none does; no setting | an install that had `auth.enabled = true` and ingest keys keeps requiring them; one without ingest keys accepts ingestion without a key until one is created |
| `authEnabled` in `GET /api/v1/auth/me` and `/api/v1/system/info` | reflected `auth.enabled` | the web UI, clients | **Retained** as always `true`; `system/info` and `GET /api/v1/api-keys` add `ingestKeyRequired` | none |
| session-cookie authentication (AUTH-PERF-02) | every request looked its session up in SQLite | the web UI, clients | **Retained**: same cookie, expiry, logout and key fallback; valid sessions are now cached in memory (bounded, invalidated by logout); `system/info` adds `sessionAuth` counters | none |
| API key `lastUsedAt` (AUTH-PERF-03) | written at most once a minute per key, one blocking task per write, the ids of every key ever used kept in memory | the web UI, clients | **Retained**: same field and one-minute throttle; written in batches by one background writer with bounded bookkeeping (at most 4096 keys, only active ones); while over 4096 keys were each used within the last minute, or the database is failing or very busy, a key's time can lag by more than a minute; a revoked key's time is no longer updated; `system/info` adds `apiKeyTouch` counters | none |

### Persisted UI state

**N/A for removal:** the UI stores one `localStorage` key, `vyrtel.columns` (a JSON list of
column names), with no versioned shape or migration. A stale or unreadable value already falls
back to the default columns; `web/tests/unit/lib.test.ts` now covers it (TC2).

### Integrations, SDKs and dependencies

* .NET tools (`dotnet/`), `tools/loadgen` and the docs site use only current routes (none used
  `/api/v1/live` or `spans`). There are no SDK or node adapters yet.
* **Dependencies:** none is compatibility-only. `flate2` is a dev-dependency for gzip test bodies;
  `async-compression` (ingest) and `tower-http` request decompression (other routes) serve
  different current paths. `telemetry` became a dependency of `metadata` for the shared layout
  identity.

## Format-version reset

FR-AC1 to FR-AC5. Before → after for every Vyrtel-owned persisted discriminator:

| Format | Constant | Before | After |
|---|---|---|---|
| Layout identity | `telemetry::LAYOUT` / `LAYOUT_TAG` | none | `"0.1.2"` |
| Data-directory format | `server::datadir::FORMAT` | 2 (also read 1, and none) | 1 |
| WAL file format | `storage::wal::WAL_FORMAT_VERSION` | 1 (24-byte header) | 1 (32-byte header with identity) |
| WAL record version | `storage::wal::RECORD_VERSION` | 1 | 1 |
| Event codec | `storage::codec::CODEC_VERSION` | 2 (also read 1) | 1 |
| Segment format | `storage::segment::FORMAT_VERSION` | 1 (32-byte header, 56-byte footer) | 1 (40 / 64 bytes with identity) |
| Metadata schema | `metadata::SCHEMA_VERSION` | 1 (`schema_migrations` chain) | 1 (`vyrtel_layout`, `application_id` `0x56595254`) |
| Quarantine names, `tmp/`, `.lock`, `indexes/` | — | not versioned | not versioned (never read as data) |

Not reset (FR-AC2): the application version, OTLP and other external protocol versions, event
ids, WAL and segment file ids, sequence numbers and checksums.

**Identity checks** (FR-AC3). The identity is read before any version or other byte: manifest
`layout`; WAL bytes 8–15; segment bytes 8–15 and footer bytes 44–51 under its CRC; metadata
`application_id` and `vyrtel_layout`. Another identity, none, one cut short, or files of another
layout mixed into this one's directory are refused before the lock is taken and before anything
changes. Restarting this release's own directories is unaffected. Details:
[storage format → Versioning](../storage-format.md#versioning).

**Deleted** historical dispatch: the codec-1 batch decoder; Observer magic recognition; the
unversioned-directory upgrade, format-1 manifest upgrade and metadata migration chain; the
release-compatibility table. Fixtures kept only as refusal inputs: `tests/fixtures/datadir/v0.1.0`
and `v0.1.1`.

## Supported contract

| Input | 0.1.2 accepts | Refused (exit 1 or HTTP error, nothing changed) |
|---|---|---|
| Data directory | new or empty; layout `0.1.2`; an interrupted first start of this build | 0.1.1, Observer 0.1.0, earlier 0.1.2 builds; any file of another layout |
| `vyrtel.json` | `format` 1, `layout` `"0.1.2"`, `writtenBy`, optional `inventory` | another or no `layout`, another `format`, unknown keys |
| Metadata database | layout `0.1.2`, schema 1; or empty | any other identity, including 0.1.1's |
| Backups | a stopped copy of a layout-`0.1.2` directory | backups of earlier releases (restore them with their own release) |
| Environment | the 27 variables in [configuration](../configuration.md#environment-variables), and any non-setting `VYRTEL_*` name | an unknown name under a settings prefix |
| Config file | the documented keys | unknown keys (unchanged) |
| API | as documented in [api.md](../api.md) | `/api/v1/live`, the `spans` signal name |
| Ingest | native JSON/NDJSON with CLEF aliases, OTLP/HTTP JSON and protobuf | unchanged |

Breaking-change notes for operators:
[configuration → Compatibility changes in 0.1.2](../configuration.md#compatibility-changes-in-012).
Clean-install and going-back procedure:
[Moving to a release with another layout](../configuration.md#moving-to-a-release-with-another-layout).

## Roadmap reconciliation

AC4: Rowan's 2026-10-19 direction supersedes blanket historical-compatibility promises.

| Issue | Promise before | Reconciled to |
|---|---|---|
| [#7](https://github.com/rowan-smith/Vyrtel/issues/7) REL-06 restore | restore a backup with any same-or-newer version | restore with a release of the same layout; partial restores still refused as before |
| [#8](https://github.com/rowan-smith/Vyrtel/issues/8) REL-07 upgrades | upgrades read older data, migrate it resumably, report downgrade options | incompatible data is refused before any change (kept); no cross-layout upgrade, migration or downgrade path |

| [#189](https://github.com/rowan-smith/Vyrtel/issues/189) STO-04 codecs | versioned codec selection that keeps reading older codecs | a codec change is a layout change: new identity, versions reset to 1, no old-codec reader before 1.0 |
| [#213](https://github.com/rowan-smith/Vyrtel/issues/213), [#219](https://github.com/rowan-smith/Vyrtel/issues/219), [#225](https://github.com/rowan-smith/Vyrtel/issues/225) MorphStore | canonical contracts, versioned segment extensions with mixed readers, staged rollout | one layout per release; extensions ship as a new layout; no mixed-layout readers or mixed-version guarantee before 1.0 |
